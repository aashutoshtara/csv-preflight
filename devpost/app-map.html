REFERENCE MAP · ACTUAL IMPLEMENTATION

One file. Two representations.
Checks at each boundary.

This app keeps original CSV bytes separate from parsed string values. It uses the strings for inspection and a review workbook; the original download always uses the retained bytes.

01Read and preservemain.ts → csv.ts

Copy the bytes, validate UTF-8 and CSV quoting, then produce literal string records.

02Inspect and explainanalyze.ts → main.ts

Locate supported risk patterns. Selecting a finding shows the exact escaped value.

03Verify and hand offworkbook.ts → integrity.ts

Build text cells, compare them to the source, and hash both files for the receipt.

A three-stop reference route

This is a reference route, not a claim that the learner completed a code tour.

  1. Choose a file: src/main.ts, load. A generation token prevents an old asynchronous result from appearing after replacement or reset.
  2. Preserve its values: src/csv.ts, parseCsv and parseView. Only one byte-level BOM is removed; outside-field line endings are normalized only in the parse view, and quoted content stays exact.
  3. Check the output: src/workbook.ts, createVerifiedWorkbook / verifyWorkbook, then src/integrity.ts, createIntegrityReceipt. Nonempty values must remain text; blanks are interpreted inside the declared rectangle. The receipt verifies source/value agreement and excludes source names and cell contents.

To change this, start here

  • Risk patterns and explanations: src/analyze.ts and tests/csv.test.ts.
  • Input limits and encoding handling: src/csv.ts; keep workbook limits consistent in src/workbook.ts.
  • Layout or visible wording: index.html, src/style.css and rendering in src/main.ts.
  • Receipt fields or privacy behavior: src/integrity.ts and tests/integrity.test.ts.
  • Public package and custom hostname: scripts/prepare-pages.mjs and vite.config.ts.

A practice to reuse

The requirement “preserve the CSV” became separate checks for source bytes, parsed strings and exported cells. Review found that mixed line endings and a second BOM could alter parsed values even when a workbook round-trip passed. Testing each boundary against expected values caught that gap.

tests/csv.test.ts covers those cases. tests/workbook.test.ts invokes an independent openpyxl reader for four fixtures. tests/integrity.test.ts rejects a same-shaped workbook containing different values. This is technical evidence, not a claim about personal learning or native Excel compatibility.
